# Архитектура проекта video2ASCII

## Обзор

Проект организован по принципам модульной архитектуры с четким разделением ответственности. Каждый модуль имеет свою область ответственности и может быть легко протестирован и модифицирован независимо.

## Структура модулей

### 1. Config (`config.h`)
**Назначение**: Централизованное хранение констант проекта.

**Содержит**:
- Набор ASCII символов для отрисовки
- Размеры и параметры по умолчанию
- Коэффициенты и константы

**Принципы**: DRY, Single Source of Truth

---

### 2. AsciiCache (`ascii_cache.h/cpp`)
**Назначение**: Кеширование преобразования пикселей в ASCII символы.

**Ответственность**:
- Предварительный расчет индексов ASCII символов
- Быстрое преобразование интенсивности пикселя в символ

**Принципы**: RAII, оптимизация производительности

**Использование**:
```cpp
AsciiCache cache;
char symbol = cache.pixelToASCII(128);
```

---

### 3. Utils (`utils.h/cpp`)
**Назначение**: Вспомогательные утилиты общего назначения.

**Функции**:
- `clearScreen()` - кроссплатформенная очистка экрана
- `isUrl()` - проверка, является ли строка URL
- `generateTempFileName()` - генерация уникальных имен временных файлов

**Принципы**: KISS, переиспользование

---

### 4. VideoDownloader (`video_downloader.h/cpp`)
**Назначение**: Загрузка видео файлов по HTTP/HTTPS.

**Ответственность**:
- Проверка наличия curl в системе
- Загрузка видео по URL
- Валидация загруженных файлов

**Принципы**: Single Responsibility, инкапсуляция

**Использование**:
```cpp
bool success = VideoDownloader::downloadFromUrl(url, outputPath);
```

---

### 5. VideoPathResolver (`video_path_resolver.h/cpp`)
**Назначение**: Унифицированное разрешение путей к видео (локальный файл или URL).

**Ответственность**:
- Определение типа источника (локальный/URL)
- Автоматическая загрузка видео по URL
- Валидация локальных файлов
- Управление временными файлами

**Принципы**: Facade Pattern, инкапсуляция сложности

**Использование**:
```cpp
std::string path = VideoPathResolver::resolve(input);
bool isTemp = VideoPathResolver::isTemporaryFile(path);
```

---

### 6. VideoProcessor (`video_processor.h/cpp`)
**Назначение**: Основной класс для обработки видео и преобразования в ASCII-арт.

**Ответственность**:
- Открытие и управление видео файлом (RAII)
- Обработка кадров (преобразование в ASCII)
- Многопоточное воспроизведение
- Управление ресурсами OpenCV

**Принципы**: RAII, многопоточность, инкапсуляция

**Потоки**:
- `processingThread()` - обработка кадров
- `playbackThread()` - воспроизведение кадров

**Использование**:
```cpp
VideoProcessor processor(videoPath, width);
processor.process();
```

---

### 7. CLI (`cli.h/cpp`)
**Назначение**: Парсинг аргументов командной строки.

**Ответственность**:
- Парсинг аргументов
- Валидация параметров
- Вывод справки

**Принципы**: Separation of Concerns

**Использование**:
```cpp
auto args = cli::parseArguments(argc, argv);
if (args.showHelp) {
    cli::printUsage(argv[0]);
}
```

---

### 8. Main (`main.cpp`)
**Назначение**: Точка входа в программу, оркестрация модулей.

**Ответственность**:
- Парсинг аргументов
- Разрешение пути к видео
- Создание и запуск процессора
- Обработка ошибок
- Очистка временных файлов

**Принципы**: Thin main, делегирование ответственности

---

## Потоки данных

```
[CLI] -> [VideoPathResolver] -> [VideoDownloader] (если URL)
                                    |
                                    v
[VideoProcessor] <- [AsciiCache] <- [Utils]
        |
        v
[Многопоточная обработка]
```

## Принципы проектирования

### RAII (Resource Acquisition Is Initialization)
- `VideoProcessor` автоматически управляет `VideoCapture`
- Деструкторы освобождают ресурсы

### Single Responsibility Principle
- Каждый класс имеет одну четкую ответственность
- Модули не смешивают различные функции

### Dependency Inversion
- Модули зависят от абстракций (интерфейсов)
- Низкая связанность между модулями

### DRY (Don't Repeat Yourself)
- Константы в `config.h`
- Переиспользование утилит

### KISS (Keep It Simple, Stupid)
- Простые и понятные интерфейсы
- Минимум абстракций

## Многопоточность

Проект использует два потока:

1. **Поток обработки** (`processingThread`):
   - Читает кадры из видео
   - Преобразует в ASCII
   - Добавляет в очередь

2. **Поток воспроизведения** (`playbackThread`):
   - Берет кадры из очереди
   - Выводит в консоль
   - Синхронизируется через `condition_variable`

**Синхронизация**:
- `mutex` для защиты общей очереди
- `condition_variable` для уведомлений
- `lock_guard` и `unique_lock` для безопасного доступа

## Расширяемость

Проект легко расширяется:

1. **Новые форматы видео**: добавить поддержку в `VideoProcessor`
2. **Новые источники**: расширить `VideoPathResolver`
3. **Новые алгоритмы ASCII**: создать новый класс, наследующий от `AsciiCache`
4. **Новые опции CLI**: расширить `cli::Arguments` и парсер

## Тестируемость

Каждый модуль может быть протестирован независимо:

- `AsciiCache` - unit тесты для преобразования
- `VideoDownloader` - mock тесты с заглушками
- `VideoProcessor` - интеграционные тесты
- `CLI` - unit тесты парсинга

## Зависимости между модулями

```
main.cpp
  ├── cli.h
  ├── video_processor.h
  │   ├── ascii_cache.h
  │   │   └── config.h
  │   └── utils.h
  └── video_path_resolver.h
      ├── video_downloader.h
      └── utils.h
```

Все зависимости направлены вниз, нет циклических зависимостей.
